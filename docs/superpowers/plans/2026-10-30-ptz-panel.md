# PTZ Panel (cams) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** cams passes each camera's PTZ capabilities and the cam-proxy's PTZ API through to the browser, and the Video page shows a collapsible PTZ panel (direction pad, zoom/focus, saved positions) for a PTZ camera while live video is shown.

**Architecture:** The server reads `capabilities` from the proxy's camera list (already read for names), keeps them per camera next to the reported name, and adds them to `GET /api/cameras`; a change makes browsers re-read the list (existing `cameras` SSE event). New routes `/api/cameras/:id/ptz/*` validate the body and relay the proxy's status and JSON as they are (the compositions pattern). The proxy's `ptz-positions` stream message is relayed to browsers as `event: ptz-positions {cam}`. The web side is a small API module, a press-and-hold helper and one component, `PtzPanel.svelte`, placed directly above `EventList`.

**Tech Stack:** Express 5, TypeScript, Svelte 5 (runes), vitest (node + jsdom), supertest, Playwright.

**Spec:** `/Volumes/SSD-WDBlack-1T/claude-work/cp-ptz/docs/superpowers/specs/2026-10-30-ptz-capabilities-design.md` (cam-proxy repo; this plan is §8.2 and the cams part of §8.3; the proxy contract is §4 and §5).

## Global Constraints

- Proxy contract (spec §4, §5) is binding; cam-proxy builds it in parallel. cams never uses Reolink terms (`PtzCtrl`, slot ids, `op`) anywhere.
- `capabilities` is `null` while unknown; cams treats `null` (and `ptz: null`) as "nothing extra". `capabilities.ptz` counts only when the proxy's `features` list contains `"ptz"`.
- Proxy error codes relayed unchanged: `not_supported` 404, `camera_offline` 503, `camera_error` 502, `limit_reached` 409, `no_free_slot` 409, `position_missing` 409, `home_position` 409, 400 `invalid`. cams's own: 404 `unknown_camera`, 404 `no_proxy`, 400 `invalid` (with `detail`), 502 `proxy_unavailable`.
- Moves: `direction` one of `left|right|up|down|left-up|left-down|right-up|right-down`; `speed` integer 1–10 (optional, proxy default 5); `durationMs` integer 100–2000 (optional, proxy default 400). Zoom `in|out`, focus `near|far`. 204 on success.
- Tap = one move call with `durationMs` 400; hold = a move call every 250 ms with `durationMs` 600; release / pointerleave / pointercancel / window blur / `visibilitychange` to hidden → `stop`.
- Positions: at most 20 (`max` from the proxy); names 1–40 characters after trimming, unique per camera case-insensitively; exactly one Home while any exist; Home can't be deleted while others exist.
- Every PTZ route is open to every member: `viewer` in `server/routes/access.ts`, and every non-GET one listed in `VIEWER_WRITES` (cams has viewer/admin roles; PTZ is for all).
- Panel: only while live video is shown (`mode === 'live'`) and `capabilities.ptz` is non-null; collapsed by default; open state per browser in `localStorage` key `cams-ptz-open` through the existing `persistedBoolean` (already wrapped in try/catch); no browser dialogs; errors inline in the panel; soft transitions only (`duration()` from `web/src/lib/motion.ts`), no flicker (the list is never cleared while reloading); the app's theme tokens (`--surface`, `--surface-2`, `--border`, `--accent`, `--muted`, `--danger`, `--radius`) and the VideoControls button look.
- Out of scope: MCP server, `llms.txt`, landing page.
- Commands: `npx vitest run <file>`, `npm run lint:types`, `npm run check`, `npm run check:svelte`, `npm run build && npx playwright test <spec>`.

## Review Focus

1. **Holding the pad for minutes** — 4 requests a second exhaust the general API limit (600 per 5 min) in 2.5 min and then everything else 429s too. Expected: PTZ control calls have their own budget and don't eat the page's. Pinned in Task 2.
2. **A hold that ends without a release** — the tab is hidden, the window loses focus, the page switches to a recording or another camera, or the component unmounts mid-hold. Expected: one `stop` for the camera that was moving. Pinned in Task 4 (helper) and Task 5 (component: camera switch and unmount).
3. **An older proxy or odd capabilities** — no `ptz` in `features`, `capabilities` missing, wrong types, `positions.max` absurd. Expected: no panel, no crash, `capabilities: null` or `ptz: null`. Pinned in Task 1.
4. **A move that fails mid-hold** (camera goes offline: 503). Expected: the repeats stop at once, the error shows inline, no request storm. Pinned in Task 4.
5. **Names a person types** — only spaces, 41+ characters, a name that differs only in case from another, renaming to the same name. Expected: an inline message and no request (same-name rename just closes the editor). Pinned in Task 4 (`checkPositionName`) and Task 6.

  ```ts
  export function moveId(ids: string[], from: number, to: number): string[]
  ```
  Every call throws `PtzError` on a non-2xx answer (code from the body's `error`); a network failure throws `PtzError(0, null)`. URLs: `/api/cameras/${encodeURIComponent(cam)}/ptz/...`.
- Error copy (`ptzErrorText`), exact:
  - `not_supported`: "This camera can't do that."
  - `camera_offline`: "The camera is offline."
  - `camera_error`: "The camera didn't accept that. Try again."
  - `proxy_unavailable` / status 0: "The camera's cam-proxy can't be reached."
  - `limit_reached`: "No room for more positions. Delete one first."
  - `no_free_slot`: "The camera has no free preset slot left."
  - `position_missing`: "This position is no longer on the camera. Save it again."
  - `home_position`: "Home can't be deleted while other positions exist. Make another position Home first."
  - 400 `invalid`: "That wasn't accepted. Check the name (1–40 characters, not used yet)."
  - 429: "Too many requests. Wait a moment."
  - anything else: "That didn't work (HTTP <status>)."
- `checkPositionName` copy: empty after trim → "Give the position a name."; > 40 → "Names are at most 40 characters."; taken by another (case-insensitive, trimmed) → "Another position already has that name."
- Produces (ptzHold.ts):
  ```ts
  export const TAP_MS = 400, HOLD_MS = 600, REPEAT_MS = 250;
  export interface Hold { press(): void; release(): void; cancel(): void; active(): boolean }
  export function createHold(o: { start(durationMs: number): Promise<void>; stop(): Promise<void>; onError(e: unknown): void }): Hold
  ```
  `press`: ignored while active; `start(TAP_MS)` now; after `REPEAT_MS` it is a hold: `start(HOLD_MS)` then every `REPEAT_MS`. `release`: ends; `stop()` only if it became a hold (a tap's 400 ms lease ends by itself). `cancel`: ends; `stop()` whenever a press was active. A rejected `start`: timers cleared, `stop()` if holding, `onError(e)`, inactive. `stop` errors go to `onError` too.

## Decisions beyond the spec (for Klaus's review)

- PTZ control calls get their own rate limit (`RATE_LIMIT_PTZ_MAX`, 1500 per 5 min) outside the general API budget, so holding the pad can't lock the page out.
- cams validates PTZ bodies itself and forwards only known fields; position ids are path-safe `[A-Za-z0-9_-]{1,64}`.
- A tap's release sends no `stop` (the 400 ms lease ends it); a hold's release does; leave/cancel/blur/hidden always stop.
- Positions load only while the panel is open; default name is the lowest unused "Position N"; duplicate names are caught in the browser (the spec gives no proxy code for them, so the proxy's 400 shows generic copy).
- Barn is the e2e PTZ camera; the PTZ spec runs serially in its own projects.
