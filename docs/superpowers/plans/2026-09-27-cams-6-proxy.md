# cams Plan 6: cam-proxy integration — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** cams uses cam-proxy (github.com/klaushofrichter/cam-proxy) where a
camera has one:
- new events appear at once (SSE relay instead of 60-second polling);
- a Timeline page scrubs the proxy's preview sprites and stills;
- recordings play from the proxy's FTP clips when the camera's Download
  fails, which is always the case on the real RLC-1224A.

Each feature falls back to today's behaviour while a camera has no proxy, or
the proxy is down.

**Architecture:**
- **Configuration:** a camera entry gets an optional
  `proxy: { url, token }`. The token is a cam-proxy **client token**. It stays
  on the server: browsers see only `proxy: true` in the camera summary, and
  every proxy request goes through cams with cams' own sign-in.
- **`server/proxy/`:**
  - `client.ts`: fetch with the bearer token, timeouts, JSON or a stream;
  - `stream.ts`: one upstream SSE subscription per proxied camera, with
    resume, reset and backoff, fanned out to browsers.
- **The browser:**
  - an `EventSource` on `/api/events/stream`, bumping the existing refresh
    ticks; polling stays as the fallback;
  - a new Timeline page;
  - the Recordings page shows proxy clips through the unchanged
    `video`/`thumb`/`download` routes.
- **Clips:** `RecordingsService` fetches the proxy clip that overlaps the
  event into the same DiskCache key when the camera's Download fails or the
  breaker is open.

**Tech Stack:** as cams today (Express 5, Svelte 5, vitest, Playwright).
Tests use a small **fake cam-proxy** (`test/proxy/fakeProxy.ts`) that
follows cam-proxy's `openapi.yaml`: its stream, clips, stills and previews
routes. e2e runs the same fake as a process.

**Spec:** cam-proxy spec §15 (`~/Development/cam-proxy/docs/superpowers/specs/2026-09-27-cam-proxy-design.md`);
cams spec §3, §5, §7; cam-proxy `openapi.yaml` for the API shapes.

## Global Constraints

- cams keeps working with no proxy configured, with a proxy that is offline,
  and with a proxy token that is refused. Each case falls back per feature
  and never errors a page.
- **The proxy token** never reaches a browser, a log line, an error message
  or a URL. Log the proxy's host only.
- **cam-proxy works in UTC milliseconds;** cams uses local dates and ISO
  strings. Conversions live in one helper with tests (DST day included).
- **`/health`** never depends on the proxy.
- **The CLAUDE.md rules:**
  - theme tokens only;
  - a `data-testid` on every element e2e uses;
  - e2e at both viewports;
  - CHANGELOG `[Unreleased]`;
  - no Playwright on the self-hosted runner.
- The SSE relay survives Knative's 600-second cut: the browser's EventSource
  reconnects, and the relay resumes from the last id.
- **Media routes:** proxy stills and sprites are media under the rate limit
  (`MEDIA_PATH`). A day of sprites is up to 1440 requests.

## Review Focus

1. **The proxy goes away mid-stream,** or answers 401/5xx.
   → The relay backs off and reconnects. Browsers see no error. Polling
   takes over while the upstream is down (the relay tells browsers the
   state).
2. **An SSE `reset`** (cams resumed from an id older than the proxy's
   retention) → the relay drops its cursor, and the browsers reload
   (refresh tick).
3. **A clip overlap:** a camera event with no proxy clip, several proxy
   clips, or a clip still uploading. → Pick the clip covering the event's
   start. Without one, show the existing "unavailable" state, never a wrong
   video.
4. **The token appears somewhere it shouldn't:** the summary, errors, logs,
   the relay's messages. → Tests grep for it.
5. **Browser reconnect storms** against the rate limit (`EventSource` retry
   every 3 s after a proxy outage). → The relay answers with `retry:` and
   keeps browsers connected while the upstream is down, instead of closing.

### Task 1: `proxy` in the camera config

**Files:** `server/cameraRegistry.ts`, `test/cameraRegistry.test.ts`,
`scripts/create-camera-user.sh`, README "Cameras", `.env.example`,
`web/src/lib/stores.ts` (the summary type)

- **The field:** `proxy?: { url: string; token: string }`.
  - `url` is an `http:`/`https:` URL with no credentials, query or hash;
    a trailing `/` is removed.
  - `token` is a string of 32 or more characters with no whitespace.
  - Anything else throws at startup, naming the camera and the field, never
    the token's value.
- **`CameraSummary`** gets `proxy: boolean`.
- **`create-camera-user.sh`** keeps every other key of cam1's entry,
  `proxy` included. Test this by running it against a fixture file if the
  script allows it; otherwise write a ruling and do a manual check.
- **Tests:**
  - valid;
  - each invalid shape;
  - the error message never contains the token;
  - `listCameras()` has `proxy: true/false` and no URL or token.

### Task 2: Proxy client and the fake cam-proxy

**Files:** `server/proxy/client.ts`, `test/proxy/fakeProxy.ts`, `test/proxyClient.test.ts`

- **`ProxyClient`:**
  - `new ProxyClient({ url, token }, { timeoutMs })`;
  - `json<T>(path, query)` returns the parsed body or throws
    `ProxyError(code)` with `'proxy_unreachable' | 'proxy_unauthorized' |
    'proxy_error'`;
  - `stream(path, init)` returns the upstream response for piping (images,
    clip files, SSE);
  - one instance per camera (cache like `reolink/clients.ts`);
  - errors carry the host, never the token.
- **The fake cam-proxy** (Express, listen 0), holding in-memory data the
  test sets:
  - `/api/stream` (SSE with ids, `since`, a `reset` case, `: ping`);
  - `/api/cameras/:cam/clips?from&to`, `/clips/:id.mp4` (Range through
    `sendFile`), `/clips/:id.jpg`;
  - `/api/cameras/:cam/previews?from&to`, `/previews/:minute.jpg`;
  - `/api/cameras/:cam/stills?from&to`, `/stills/:ts.jpg`.

  It refuses a wrong bearer with 401 as cam-proxy does, and has switches:
  `offline`, `refuseToken`, `dropStream`.
- **Tests:** JSON happy path, 401 → `proxy_unauthorized`, connection refused
  → `proxy_unreachable`, timeout, the token absent from error messages.

### Task 3: SSE relay

**Files:** `server/proxy/stream.ts`, `server/routes/events.ts` (registered in
`server/routes/api.ts`), `server/recordings/service.ts` (`invalidateDay`),
`test/proxyStream.test.ts`, `web/src/lib/eventStream.ts`,
`web/src/lib/eventStream.test.ts`, `Recordings.svelte`, `Live.svelte`

- **Upstream** (`ProxyStream`, one per proxied camera):
  - `GET <url>/api/stream?types=camera-event,camera-status,clip&since=<lastId>`;
  - parses SSE frames (id, event, data);
  - on `reset`, it clears `lastId`;
  - on error or end, it reconnects with backoff (1 s doubling to 30 s),
    resetting after 60 s of health;
  - it emits `message` ({cam, type, data}) and `state` ('up' | 'down');
  - `stop()` for shutdown.

  It starts at server start for cameras with a proxy, and stops on
  SIGTERM.
- **Side effects:** `clip` and `camera-event` (`phase: 'end'`) call
  `getRecordings().invalidateDay(cam, localDate(ts))`, so the next
  `/events` fetch is fresh.
- **Browser route** `GET /api/events/stream`:
  - behind `requireAuthApi` as every `/api` route, `text/event-stream`,
    `flushHeaders`, `X-Accel-Buffering: no`;
  - writes `retry: 5000` and the current state of each camera
    (`event: proxy` `{cam, up}`);
  - then relays `event: change` `{cam, type, ts}`: no clip URLs and no
    tokens; the browser reloads through the existing APIs;
  - `: ping` every 25 s;
  - at most 20 browser connections (503 beyond).
- **Browser** `eventStream.ts`:
  - one shared EventSource opened on the app shell, only when some camera
    has `proxy`;
  - a store `{connected, up: Record<cam, boolean>}` plus a subscribe for
    changes;
  - `Recordings.svelte` and `Live.svelte` bump their refresh tick on a
    `change` for the camera shown (debounced 1 s);
  - `createTodayRefresher` keeps running only when the camera has no proxy
    or the stream isn't `up`.
- **Tests:**
  - upstream against the fake: messages, resume with `since` after
    `dropStream`, reset, backoff when offline, 401 → down (with a slower
    retry);
  - the route: auth required, relays, cap, no token in any frame;
  - the web lib with a fake EventSource: fallback switching, debounce.

### Task 4: Timeline page

**Files:** `server/routes/proxy.ts` (media pass-through),
`server/middleware/rateLimit.ts` (`MEDIA_PATH`), `web/src/lib/router.ts`,
`web/src/App.svelte`, `web/src/pages/Timeline.svelte`,
`web/src/lib/timeline.ts` (+ test), `test/proxyRoutes.test.ts`, e2e
`e2e/timeline.spec.ts`

- **Pass-through** (auth, and 404 `no_proxy` for a camera without one):
  - `GET /api/cameras/:id/previews?from&to` (JSON; `url`s rewritten to cams'
    own `/api/cameras/:id/previews/:minute.jpg`);
  - `/previews/:minute.jpg`, `/stills?from&to`, `/stills/:ts.jpg`.

  Images stream through with the proxy's `Content-Type` and caching headers.
  Validate the parameters as cam-proxy does (digits only, at most a day).
- **`MEDIA_PATH`** covers the two image routes.
- **Page `timeline`** (nav "Timeline", after Recordings; shown only when some
  camera has a proxy):
  - camera picker (proxied cameras), day picker (local day → UTC range via
    `timeline.ts`);
  - hour rows of minute tiles from the sprites, loaded lazily
    (IntersectionObserver);
  - event marks from `/api/cameras/:id/events?date` (the existing API);
  - clicking a tile shows the still for that second in a viewer, with
    left/right to step by seconds;
  - live updates through `eventStream` when the day is today;
  - the URL cursor `?cam&date&t`;
  - `data-testid`s; theme tokens; works at 390 px (fewer columns).
- **Tests:**
  - routes against the fake (auth, `no_proxy`, parameter checks, rewritten
    URLs, image streaming);
  - `timeline.ts` (local day → range across the DST days, tile position for
    a second);
  - e2e: the page shows the day's tiles and a still for a click, at both
    viewports.

### Task 5: Clips from the proxy

**Files:** `server/recordings/service.ts`, `server/recordings/proxyClips.ts`,
`test/recordingsService.test.ts`, `test/recordingsRoutes.test.ts`,
`Recordings.svelte`, `ClipPlayer.svelte`, e2e

- **`withClip(cam, clipId)`**, for a camera with a proxy, when the camera
  download fails (after the retry) or the breaker is open:
  - look up the proxy clips overlapping the event (`/clips?from=start-60s&to=end`);
  - pick the one whose `[start,end]` contains the event's start, or else
    the nearest start within 60 s;
  - stream `/clips/{id}.mp4` into the same DiskCache key, and use the
    proxy's `.jpg` for `thumb.jpg` when the clip has a snapshot.

  Without a match, keep today's error (`recordings_unavailable` or 404).
  The breaker still counts only the camera's refusals.
- **`openDownload(quality)`:** the proxy clip, whatever quality was asked
  for, and the file name says so (`…-proxy.mp4`). The proxy stores one
  stream, the one set in its `ftp.stream`.
- **`downloadsState()`** becomes `'ok' | 'proxy' | 'unavailable'`. It is
  `'proxy'` when the breaker is open and the camera has a proxy that is up.
  The Recordings page shows no "unavailable" banner in that state, and a
  small note "from the camera gateway".
- **Tests:**
  - the service with cam-sim `downloads.refuse` plus the fake proxy with a
    clip: video and thumbnail served from the proxy;
  - an event without a proxy clip → unchanged error;
  - two overlapping clips → the right one;
  - proxy offline → unchanged error;
  - the route test for `downloads: 'proxy'`;
  - e2e: camera "shed" (refuses downloads) gets the fake proxy, and its
    clip plays.
